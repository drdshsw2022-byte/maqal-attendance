# نظام الحضور والغياب بالـ QR — جامعة المعقل الأهلية (البصرة)

مشروع من جزأين:

| المجلد | الوظيفة |
|---|---|
| `server/` | الخادم (Python + Flask + SQLite): قاعدة الطلاب والمواد، الدخول، رمز QR المتجدد، الحضور، التقارير، تصدير Excel |
| `app/` | تطبيق الهاتف (Python + Kivy) بثلاث لوحات: **المدير** و**الدكتور** و**الطالب** |

> التطبيق لا يحمل أي بيانات طلاب؛ كل البيانات على الخادم فقط.

## 1) تشغيل الخادم

```bash
cd server
pip install -r requirements.txt
python manage.py init --admin-email you@gmail.com     # يستورد 538 طالباً و136 مادة، ويطبع كلمة مرور المدير مرة واحدة
gunicorn -w 2 -b 127.0.0.1:8000 wsgi:app              # أو: python manage.py run --port 8000
```

* **يلزم HTTPS** حتى يعمل التطبيق على أندرويد (يمنع الاتصال غير المشفّر افتراضياً). أبسط طريقة: Caddy أمام الخادم — انظر `server/Caddyfile.example`.
* النسخ الاحتياطي: انسخ مجلد `server/instance/` (فيه قاعدة البيانات `attendance.db` والمفتاح السري).
* لتحديث الطلاب لاحقاً: `python manage.py import-students ملف.xlsx` (لا يمس حسابات المفعّلين).
* عند توفر أقسام الطلاب: `python manage.py import-departments ملف.xlsx` (عمودان: الرقم المعرفي، القسم `ai` أو `control` أو `cyber`).

## 2) بناء ملف APK (بدون تثبيت أي شيء على جهازك)

1. ضع عنوان خادمك في `app/config.py` (`DEFAULT_SERVER`)، أو اتركه فارغاً ويُدخله المستخدم من «إعدادات الخادم».
2. أنشئ مستودعاً **خاصاً (Private)** على GitHub وارفع محتويات هذا المجلد.
3. تبويب **Actions ← Build APK ← Run workflow**، وبعد 15–30 دقيقة نزّل `app-debug.apk` من **Artifacts**.
4. انسخه إلى الهاتف وثبّته (فعّل «التثبيت من مصادر غير معروفة»).

> ملف `.gitignore` يمنع رفع قاعدة البيانات وملفي Excel الخاصين بالطلاب. لا تجعل المستودع عاماً.
> هذا إصدار debug للتوزيع المباشر. النشر على Google Play يتطلب توقيع إصدار release.

## 3) طريقة العمل

* **المدير:** يضيف الدكاترة (بريد + كلمة مرور مؤقتة)، ويُسند لكل دكتور موادَّه، ويضبط الفصل الحالي ونسب التأخر والإنذار، ويتابع الطلاب (فك ارتباط الهاتف، إعادة تعيين حساب، تعيين القسم).
* **الدكتور:** يختار مادته ← «بدء محاضرة» ← يعرض رمز QR على الشاشة (يتجدد كل 20 ثانية). يرى الحاضرين لحظياً ويعدّل الحالة يدوياً (حاضر/متأخر/بعذر/غائب)، ثم ينهي المحاضرة. في «التقارير» نسب الحضور لكل طالب وتصدير Excel.
* **الطالب:** أول مرة: «تفعيل حساب الطالب» بالرقم المعرفي ← يختار القسم ← كلمة مرور (وبريد Gmail اختياري). بعدها يدخل بالرقم أو بالبريد، ويمسح الرمز أو يكتبه (6 أرقام).

الدخول: الرقم المعرفي (10 أرقام) **أو** البريد الإلكتروني + كلمة المرور.

## 4) الأمان وضد الغش

* رمز الحضور موقّع من الخادم ويتبدل كل 20 ثانية (تُقبل الفترة الحالية والسابقة فقط).
* حساب الطالب **يرتبط بهاتف واحد** عند التفعيل؛ لا يسجّل بهاتف آخر. المدير يفكّ الارتباط عند تغيير الهاتف.
* حدّ للمحاولات الخاطئة (دخول، تفعيل، إدخال الرمز)، وكلمات المرور مشفّرة.
* لا تتجاوز المحاضرة 4 ساعات (تُغلق تلقائياً).

## 5) ملاحظات مهمة وحدود

* **الدخول بحساب Google:** يقبل التطبيق بريد Gmail كاسم دخول (يربطه الطالب بحسابه) مع كلمة مرور. زر «Sign in with Google» الحقيقي (OAuth) يحتاج إنشاء Client ID في Google Cloud باسم جامعتكم ولا يمكن تضمينه هنا.
* **قسم الطالب:** ملف الطلاب لا يتضمن القسم، فيختاره الطالب عند التفعيل (أو يعيّنه المدير). الطالب الذي لم يفعّل حسابه لا يظهر في كشف المادة ولا يُحتسب غائباً حتى تُعيَّن أقسام الجميع — وتظهر للدكتور ملاحظة بعددهم.
* مسح الكاميرا يستخدم ماسح Google (Play Services)؛ إن لم يتوفر على الهاتف فالإدخال اليدوي للرمز يعمل دائماً.
* الشعار المضمّن تصميم عام؛ استبدل `app/assets/logo.png` و`icon.png` بشعار الجامعة الرسمي.
* لو رفض البناء الاسم العربي للتطبيق، غيّر `title` في `buildozer.spec` إلى اسم إنجليزي.
